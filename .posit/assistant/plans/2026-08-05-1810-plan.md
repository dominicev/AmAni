# Plan: add `secondary_data_file` to `run_animal_model()`

## Goal
Add a `secondary_data_file` argument to `run_animal_model()` in
[AmAni.manager.R](AmAni.manager.R). Default `NULL` preserves current behavior.
When set to a relative path (like `data_file`), both files are read and
row-bound into a single combined CSV, and the rest of the pipeline runs on that
combined file unchanged.

## Decisions (confirmed with user)
1. **Where to combine:** In the manager. Read both files, row-bind, write one
   combined CSV, and point `.amani_data_file` at it. Sourced scripts stay
   untouched.
2. **Clean interaction:** Combine first, then clean the combined file. The
   existing `clean` block runs on the combined CSV.
3. **XLSX:** If `secondary_data_file` is non-NULL and `data_file` (or the
   secondary file) is `.xlsx`, error out with a clear message that
   `secondary_data_file` is not supported for XLSX.

## Changes (all in `run_animal_model()`)

### 1. Signature
Add `secondary_data_file = NULL` to the argument list (after `data_file`).

### 2. Roxygen-style comment block
Document the new argument: default `NULL` (current behavior). When a relative
path is given, `data_file` and `secondary_data_file` are read and row-bound by
matching column names (missing columns filled with `NA`) into a single combined
CSV; not supported for `.xlsx` inputs.

### 3. Combine step (inserted after the extension/script switch, before the
existing `clean` block so "combine first, then clean" holds)

```r
if (!is.null(secondary_data_file)) {
  # Combining is only supported for the GBIF CSV/TSV/zip path.
  sec_ext <- tolower(tools::file_ext(secondary_data_file))
  if (ext == "xlsx" || sec_ext == "xlsx") {
    stop("secondary_data_file is not supported for XLSX (Darwin Core Excel) input.",
         call. = FALSE)
  }

  # Small reader that mirrors the script's fread_auto (handles zip + tsv).
  read_any <- function(rel_path) {
    p <- file.path(stage_dirs$animals, rel_path)
    e <- tolower(tools::file_ext(rel_path))
    if (e == "zip") {
      inner <- grep("\\.(csv|tsv)$", unzip(p, list = TRUE)$Name,
                    ignore.case = TRUE, value = TRUE)[1]
      if (is.na(inner)) stop("No CSV/TSV found inside: ", rel_path, call. = FALSE)
      inner_sep <- if (tolower(tools::file_ext(inner)) == "tsv") "\t" else ","
      cmd <- sprintf('unzip -p "%s" "%s"', normalizePath(p, winslash = "/"), inner)
      data.table::fread(cmd = cmd, sep = inner_sep)
    } else {
      data.table::fread(file = p, sep = if (e == "tsv") "\t" else ",")
    }
  }

  message("  Combining primary + secondary data files ...")
  combined <- data.table::rbindlist(
    list(read_any(data_file), read_any(secondary_data_file)),
    use.names = TRUE, fill = TRUE
  )

  combined_rel <- file.path("data", sprintf("combined_%s.csv", organism))
  combined_abs <- file.path(stage_dirs$animals, combined_rel)
  if (!dir.exists(dirname(combined_abs))) dir.create(dirname(combined_abs), recursive = TRUE)
  data.table::fwrite(combined, combined_abs)

  message("  Wrote combined file (", nrow(combined), " rows): ", combined_rel)

  # Downstream reads a single combined CSV.
  data_file <- combined_rel
  ext <- "csv"
  script <- "scripts/01_GBIFAnalysis.R"
}
```

- `use.names = TRUE, fill = TRUE` binds by matching headers and fills mismatched
  columns with `NA` ("same column headers" behavior).
- The combined CSV is written under `2-ModellingAnimals/data/` as a relative
  path so the existing `clean` block and `.amani_data_file` logic work unchanged.
- Because this runs before the `clean` block, `clean = TRUE` will clean the
  combined file (combine first, then clean).
