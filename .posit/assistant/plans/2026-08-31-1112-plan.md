# Fix out-of-memory crash in `simulateScaledSpeciesRichness` for high-diversity organisms

## Problem

For organisms with very high diversity (>100k simulated species), the simulation
exhausts RAM and crashes the machine, in **both serial and parallel** modes.

## Root cause (three compounding issues)

1. **List-of-data.frames representation.** `simulate_species_chunk()` builds one
   small `data.frame` per species
   (`records[[j]] <- data.frame(scientificName=..., grid_id=...)`). With >100k
   species this is a list of >100k tiny data.frames, each carrying large
   per-object overhead (attributes, class, row.names). This is far heavier than
   the underlying integer data.

2. **Everything held at once, then copied repeatedly.** In serial mode there is a
   single chunk, so *all* records live in memory simultaneously. In parallel mode
   every worker ships its full record list back to the main process, which
   `unlist()`s them all together. The wrapper then:
   - `Map()`s over the whole list to add `scientificName` (a full copy),
   - assigns it to the global `sim_records`,
   - `dplyr::bind_rows(sim_records)` into `sim_species_df` (another full copy),
   - `left_join(grid_sf)` + `st_as_sf()` into `sim_species_sf` — the full table
     **with polygon geometry** — *only to compute `length(unique(scientificName))`*.
   Downstream, [`02_animalAnalysis.R:923`](../../2-ModellingAnimals/scripts/02_animalAnalysis.R)
   does `do.call(rbind, sim_records)` yet again. Peak memory is roughly the full
   occurrence table held 3–4×, one copy carrying geometry.

3. **Redundant geometry build.** The wrapper's `sim_species_sf` (with geometry) is
   never used except for a count; the real geometry join for export happens
   downstream. It is pure waste.

## Confirmed downstream contract

- `sim_records` (global) is consumed only at
  [`02_animalAnalysis.R:923`](../../2-ModellingAnimals/scripts/02_animalAnalysis.R)
  via `do.call(rbind, sim_records)` → `simulated_occurrence_df` (columns
  `scientificName`, `grid_id`), which is then joined to geometry and exported to
  CSV/RDS, and used for `length(unique(scientificName))`.
- The wrapper's local `sim_species_df` / `sim_species_sf` are used only for the
  count and are safe to remove (other references are in `archive/` or commented).

## Decisions (confirmed with user)

- Edit **both** `SimulateScaledRichness.R` and `02_animalAnalysis.R`.
- Chunk files written as **RDS** (no new dependencies).
- Per-chunk **unique** `scientificName` values are acceptable (downstream relies
  only on uniqueness and counts, not the exact `SimSpp0000001` format).

## Approach

Combine a compact columnar representation with the user's disk-chunking idea so
that (a) no phase holds the whole occurrence set as a list of data.frames, and
(b) the redundant geometry build is removed.

### 1. Compact chunk records + write each chunk to disk
`simulate_species_chunk()` (in `SimulateScaledRichness.R`):
- Replace the list-of-data.frames accumulation with two growing **integer**
  buffers: `grid_id` per occurrence and a per-species integer id. Assign each
  species a chunk-unique `scientificName` of the form
  `sprintf("SimSpp_c%05d_%07d", chunk_id, local_species_id)` (uniqueness across
  chunks guaranteed by `chunk_id`).
- Add a `chunk_id` argument (needed for the name prefix).
- At the end, assemble a single compact `data.table`
  (`grid_id` integer, `scientificName` character) for the chunk, write it to
  `file.path(chunk_dir, sprintf("chunk_%05d.rds", chunk_id))`, and **return only**
  the file path, the species count, and the frontier-exhaustion diagnostics
  (`n_exhausted`, `total_shortfall`, `max_shortfall`). No records are returned in
  memory. This is what keeps parallel workers from shipping big payloads back.

### 2. Force chunking on the serial path too
In `simulate_species_records_clustered()`:
- Currently serial → `n_chunks = 1` (everything in memory). Change to chunk the
  job vector by a target size (e.g. `chunk_target_species` ≈ 5,000 species/chunk;
  tunable) so serial runs also stream to disk, one chunk in memory at a time.
- **Reproducibility:** for the serial path use *contiguous* chunks (not
  round-robin) processed in order, so the RNG draw sequence is identical to the
  original single-loop implementation. Keep round-robin only for the parallel
  path (load balancing), matching current behaviour. (Parallel already does not
  reproduce serial bit-for-bit, as documented in the function.)
- Create `chunk_dir` (default
  `file.path(project_root, "output", "shared", "sim_chunks_<runtag>")`), passed
  to every `run_chunk()` call. Register cleanup so files are removed after the
  combine step (and on error).

### 3. Combine at the end without geometry, cheaply
Replace lines ~586–618 of `simulate_species_records_clustered()`:
- Aggregate diagnostics from the returned per-chunk summaries (unchanged logic,
  just reads counts instead of record lists).
- Set a global with the **chunk file paths** (e.g. `sim_records_files`) and/or
  `rbindlist()` the chunk RDS files into a single compact `data.table`
  `simulated_occurrence_dt` (grid_id + scientificName). This is one compact copy
  (integer + character) rather than a list of >100k data.frames.
- Compute total species count = sum of per-chunk species counts (exact, since one
  species = one unique name).

### 4. Simplify the wrapper (`simulateScaledSpeciesRichness`)
Replace lines ~920–954:
- Delete the `sim_species_df` / `sim_species_sf` construction (the geometry join).
- `central_gamma` = the total species count returned from the combine step
  (equivalently `data.table::uniqueN(simulated_occurrence_dt$scientificName)`),
  no geometry needed.
- Keep the existing `sampling_model_bounds` return logic unchanged.

### 5. Update the downstream consumer (`02_animalAnalysis.R`)
- Line 923: replace `simulated_occurrence_df <- do.call(rbind, sim_records)` with
  a direct reference to the combined `simulated_occurrence_dt`
  (`simulated_occurrence_df <- as.data.frame(simulated_occurrence_dt)`), or read
  and `rbindlist()` the chunk files if we expose paths instead. Everything after
  (geometry join, CSV/RDS export, `length(unique(...))`) stays the same.

## Memory outcome

- Simulation phase: at most ~one chunk (~5k species) of records in memory at a
  time; parallel workers return only tiny summaries + file paths.
- Combine/export phase: a single compact `data.table` (integer `grid_id` +
  character name) instead of a list of data.frames plus a geometry-laden `sf`
  copy. The redundant per-run geometry build is eliminated entirely.

## Risks / notes

- **`scientificName` format changes** to `SimSpp_c#####_#######`. Only uniqueness
  and counts are used downstream, so this is safe, but the exported CSV/RDS will
  show the new names. Flag in commit message.
- **Reproducibility** of serial runs is preserved via contiguous, in-order
  chunking. Parallel runs remain non-reproducible vs serial (pre-existing).
- The **final export** in `02_animalAnalysis.R` still materialises the full sf
  object to write CSV + RDS; that is inherent to producing a combined output. If
  that step alone is still too large at extreme diversity, a follow-up could
  stream chunk files straight to an appended CSV — noted but out of scope here
  unless requested.
- `simulate_ranges` handling (including the `"BestOnly"` string path) is left
  exactly as-is; the compact accumulation works identically for the
  single-cell-per-species fast path.

## Validation plan

   (serial mode → identical counts; row counts equal).
2. Confirm chunk files are created and cleaned up.
3. Run (or dry-run reason about) a high-diversity organism to confirm peak RSS
   stays bounded (spot-check with `gc()` / `mem_used()` around the call).
4. Confirm the CSV/RDS exports are produced and `length(unique(scientificName))`
