# Plan: make plant-richness cache aware of `fill_plants`

## The question
Can we compute plant richness once per plant-data type (filled vs unfilled), cache
each separately, and just crop per analysis — and does this fit the current code?

**Short answer: yes, it fits well, but one piece is currently missing.** The cache
today is keyed by nothing (a single file), so switching `fill_plants` between runs
silently reuses the wrong richness. The cropping half of your idea already matches
the code. The only real work is teaching the pipeline which type it is running so it
picks the right cache.

## How the pieces currently connect
- `run_animal_model(fill_plants = ...)` in `AmAni.manager.R` loads either the filled
  (`species_c4_filt_interpolated.rds`) or unfilled (`species_counts4_filtered.rds`)
  plant data into the global `occ_sf`. It sets several `.amani_*` globals but **never
  exposes `fill_plants`** to the sourced scripts (only `.amani_fillAnimals` is set).
- `01_GBIFAnalysis.R` / `01_CockroachAnalysis.R` call `modelAnimal(...)`, which sets
  `redoeverything <<- ...` and sources `02_animalAnalysis.R`.
- In `02_animalAnalysis.R`, `species_counts <- occ_sf` (line 140), then
  `compute_plant_richness(species_counts, redoeverything)` (line 339).
- `compute_plant_richness()` (line 297) always reads/writes the single
  `plant_richness_cache.rds`. `cache_file_Filled` (`filled_plant_rich_cache.rds`) is
  declared at line 303 but never used. The in-memory shortcut at line 306 reuses a
  global `plant_richness` with no notion of fill state.
- `ModelAnimal.R` (lines 28-34) deliberately does **not** clear `plant_richness`
  between runs, on the assumption it is "organism-independent." With `fill_plants`
  that assumption is now false.
- Downstream, the full-extent richness is cropped per analysis:
  `plant_richness_overlap <- st_crop(plant_richness, overlap_bbox)` (line 366). So
  "compute once, crop every analysis" is already how it works — cropping happens
  after retrieval and is independent of the cache.

## The gap
Two caches are useless unless the code knows which type the current run is. Because
`fill_plants` never reaches `compute_plant_richness()`, and because the in-memory
`plant_richness` is never invalidated on a type switch, a filled run can pollute the
unfilled cache (and vice versa), and same-session type switches with `redo = FALSE`
reuse stale in-memory data.

## Proposed changes

1. **Propagate the flag** (`AmAni.manager.R`)
   - In `run_animal_model()`, add `.amani_fill_plants <<- fill_plants` alongside the
     other `.amani_*` assignments.
   - Add `".amani_fill_plants"` to the cleanup vector in `restore_wd()`.

2. **Make `compute_plant_richness()` fill-aware** (`02_animalAnalysis.R`, ~line 297)
   - Add a `fill_plants` argument (default `FALSE`).
   - Pick the cache path: `cache_file <- if (fill_plants) cache_file_Filled else
     plant_richness_cache.rds`.
   - Fix the in-memory shortcut so it only reuses the global `plant_richness` when it
     matches the current type. Track the loaded type in a global marker (e.g.
     `.plant_richness_fill_state`) and recompute/reload when it differs. (Simpler
     fallback: drop the in-memory shortcut and rely on the on-disk cache, since
     `readRDS` is cheap relative to recomputation.)
   - Update the call site (line 339) to
     `compute_plant_richness(species_counts, redoeverything, fill_plants =
     isTRUE(get0(".amani_fill_plants", ifnotfound = FALSE)))`.

3. **Fix the stale-object assumption** (`ModelAnimal.R`, lines 28-34)
   - Update the comment, and either clear `plant_richness` between runs or rely on the
     fill-state marker from step 2 so a type switch never reuses the wrong object.

4. **Repopulate the caches cleanly (one-time)**
   - The existing `plant_richness_cache.rds` may already hold filled data from a prior
     run. After the code change, run each type once with `redo = TRUE` (or delete the
     old cache file) so `plant_richness_cache.rds` (unfilled) and
     `filled_plant_rich_cache.rds` (filled) are each written from the correct source.

## Notes / edge cases
- `run_plant_model()` also drives the pipeline but never sets `fill_plants`; the
  default `FALSE` (unfilled) is correct there, since it uses
  `species_counts4_filtered.rds`.
- No downstream change is needed for cropping — `st_crop(plant_richness, overlap_bbox)`
  already runs per analysis after the cache is loaded.
- Cache filenames map naturally to the source data:
  unfilled -> `plant_richness_cache.rds`, filled -> `filled_plant_rich_cache.rds`.

## Files to touch
- `AmAni.manager.R` (set + clean up `.amani_fill_plants`)
- `2-ModellingAnimals/scripts/02_animalAnalysis.R` (`compute_plant_richness` + call)
- `2-ModellingAnimals/scripts/utils/ModelAnimal.R` (stale-object handling/comment)
