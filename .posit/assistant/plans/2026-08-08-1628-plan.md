# Diagnosis & fix: `fill_animals` failure in ModelAnimal.R line 243

## What happened

Running `run_animal_model("butterfl-curated", ..., fill_animals = TRUE, ...)`
(AmAni.run.R lines 58-69) failed inside the `if(fill_animals){...}` block at
`ModelAnimal.R:243`, specifically in the call

```r
grid_covariates <- build_grid_cell_covariates(animal_grid)   # line 244
```

The console error is:

```
Error in `summarise()`:
i In argument: `n_records = sum(count)`.
i In group 1: `grid_id = 6557`.
Caused by error in `sum()`:
! invalid 'type' (closure) of argument
Warning: Unknown or uninitialised column: `count`.
```

## Root cause

`build_grid_cell_covariates()` calls `compute_cell_completeness()`
(`1-FilteringPlantData/scripts/fillingRanges.R:106-124`), which does:

```r
occData |>
  st_drop_geometry() |>
  group_by(grid_id) |>
  summarise(
    n_records = sum(count),
    Sobs      = n_distinct(scientificName),
    f1        = sum(count == 1),
    f2        = sum(count == 2),
    ...
  )
```

This function was written for **plant occData**, which is stored as one row
per species-per-cell with an aggregated `count` column (number of records for
that species in that cell). The Chao1 math relies on that: `f1`/`f2` are the
counts of singleton/doubleton species.

The **`animal_grid`** passed in has a different schema: it is **one row per
raw occurrence record** (columns like `grid_id`, `Morphotype`,
`scientificName`, geometry) with **no `count` column**. Because `count` does
not exist as a column, R falls back to the function `dplyr::count` (a
closure), so `sum(count)` throws `invalid 'type' (closure) of argument`, and
you see the `Unknown or uninitialised column: count` warning.

Note that elsewhere in `ModelAnimal.R` (lines 93-111) the code already handles
the animal schema correctly by first aggregating with
`dplyr::count(grid_id, Morphotype, name = "abundance")`. The completeness
helper in `fillingRanges.R` never got that treatment, so it only works on
plant-format data.

This is a schema mismatch, not a data problem — it will fail for **any**
animal dataset run with `fill_animals = TRUE`, not just butterflies.

## Proposed fix

Make the completeness calculation robust to the animal (one-row-per-record)
schema. Preferred approach — adapt `compute_cell_completeness()` in
`fillingRanges.R` so it derives per-species record counts itself instead of
assuming a pre-aggregated `count` column:

1. Drop geometry.
2. If a `count` column is absent, first aggregate to species-per-cell counts
   (`group_by(grid_id, <species col>) |> summarise(count = n())` or
   `dplyr::count(..., name = "count")`), so each row is one species in one
   cell with its record total.
3. Then compute `n_records`, `Sobs`, `f1`, `f2`, `chao1`, `completeness` as
   now.
4. Decide the species column: the plant path uses `scientificName`; animal
   data uses `Morphotype` for the abundance aggregation (line 95) but also
   carries `scientificName`. We should confirm which column is the correct
   unit of "species" for the butterfly animal_grid before finalizing, to keep
   Chao1 consistent with the rest of the animal pipeline.

Alternative (smaller, but less general): leave `compute_cell_completeness()`
alone and instead pre-aggregate `animal_grid` into the expected
`grid_id / scientificName / count` shape at the `ModelAnimal.R:244` call site
before passing it to `build_grid_cell_covariates()`.
